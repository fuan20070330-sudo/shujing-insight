# 数镜 · 答辩功能清单

## 一、作品定位

- 赛事方向：中国大学生计算机设计大赛 · 大数据应用 / 信息可视化 / 软件应用与开发。
- 作品形态：纯软件、静态 Web 应用，可在 GitHub Pages 部署。
- 核心命题：自动洞察不能只给“结论”，还必须让评委看到结论如何从原始数据、筛选条件、统计方法和证据表中产生。
- 技术关键词：React、TypeScript、Vite、Web Worker、ECharts、浏览器内统计、可追溯证据链。

## 三、评委可现场操作的亮点

### 1. 首页叙事

打开页面后，先看到“让每一个结论，都有一条回家的路”，以及“输入 → 证据 → 叙事”三步流程。它明确表达作品不是传统管理后台，而是证据驱动的数据叙事工具。

### 2. 证据链透明

选中一条洞察后，会同时看到：

- 排序分与置信标记；
- 有效样本量；
- 形式化统计方法；
- 效应量；
- p 值；
- 推荐图表及推荐理由；
- 数据视图 → 统计方法 → 证据口径的追溯条。

点击“打开完整证据抽屉”，可以查看并复制可审计证据链。

### 3. 真实追问

点击“下钻至最高组”或“查看变点后的记录”，系统会：

1. 新增结构化筛选条件；
2. 在 Web Worker 中重新分析；
3. 更新全部洞察与证据；
4. 在页面保留追问链。

这体现“追问式下钻”，不是静态跳转。

### 4. 质量先行

切换到“质量检查”标签，可以看到缺失和 IQR 异常的具体字段、数量与原因。异常不会被自动删除，结论会保留对数据质量的提醒。

### 5. 报告可带走

点击“导出报告”生成 HTML 审计报告；点击 MD 生成 Markdown。报告包含方法、样本量、效应量、p 值、证据表和解释边界。

## 四、创新点表述

1. Evidence-first 自动洞察：把“洞察”定义为可复核的统计主张，而不是一段无法验证的自然语言。
2. 证据链即交互对象：筛选、追问、图表和导出共享同一组结构化条件，避免叙事与计算脱节。
3. 本地计算的可信路径：不依赖外部 AI API，也能完成自动分析、排序与叙事骨架；后续网关只做可选增强。
4. 质量风险进入排序：缺失和异常不是单独页面，而是与业务洞察同台竞争注意力。
5. 面向比赛演示的叙事化界面：从首页命题到工作台证据，再到报告导出，形成完整演示闭环。

## 五、答辩时建议主动说明的限制

- 小样本或筛选后样本不足时，不强行输出高置信结论。
- 相关性、分组差异和变点都不等于因果。
- 多重比较没有做全族错误率校正；因此作品把方法、效应量和边界明确展示，便于人工复核。
- 目前是单变点扫描，不覆盖多季节、强自相关等复杂时间序列场景。
- 文件上限 20 MB、分析上限 50,000 行；更大规模需要后续接入流式或远程分析。
- 静态站不能提供协作、持久化和 WebSocket 服务；VITE_WS_GATEWAY_URL 只是可选增强入口。

## 六、现场故障预案

1. 如果现场网络不可用：本地执行 npm run build 和 npm run preview，功能与线上一致。
2. 如果示例数据加载失败：使用 public/demo/smart-community-demo.csv 本地导入。
3. 如果图表未出现：切换一条洞察或缩放窗口触发 ECharts 自适应；刷新后重试。
4. 如果评委追问统计细节：打开证据抽屉，逐项展示方法、样本量、效应量和证据表。
5. 如果问“没有 AI 怎么自动洞察”：回答核心是字段类型推断 + 多方法统计检验 + 效应量阈值 + 证据排序 + 规则化图表推荐，并非大模型生成。
